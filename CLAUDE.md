# CLAUDE.md

Ориентир для Claude Code при работе в этом репозитории.

## Что это

«ОРБИТА» — исследовательский прототип поддержки решений для КосмоХакатона 2026,
задача «Прогнозирование внешних рисков и планирование ВКД на МКС». Сервис
помогает аналитику наземной группы сравнить окна внекорабельной деятельности
(1–8 ч, сдвиг начала до 24 ч) по внешней обстановке на траектории станции.

Оценивается по критериям жюри: отраслевые О1–О7 (факторы, интерпретация,
сравнение окон, доказательства, удобство, презентация, доп. функции) и
технические Т1–Т8 (данные, орбита, методы, исторический режим, эксперименты,
надёжность, качество кода, воспроизводимость). Почти каждое архитектурное
решение ниже существует ради конкретного критерия — не «упрощайте» их.

Развёрнутый стенд: http://2.26.77.44/ · репозиторий: `Tr1pel/CosmoHack_SPB`.

## Команды

```sh
npm ci                 # Node.js 20+
npm run dev            # локальный API + статика на http://127.0.0.1:5173
npm test               # node --test tests/*.test.mjs (5 тестов моделей — только с PIPELINE_PYTHON)
npm run check          # синтаксис + совпадение dist/ и docs/
```

Пайплайн (см. `docs/data-pipeline.md`):

```sh
npm run pipeline:fetch -- data/request.example.json local/history.json
npm run pipeline:build -- data/request.example.json local/offline.json
npm run pipeline:import -- omm|goes|hp30|nmdb|socrates|donki|geoalert|records FILE
npm run meteor:table
```

Переменные окружения: `PIPELINE_PYTHON` (путь к venv-питону; без неё IGRF/AP-8
недоступны и механизм «захваченные частицы» пустой), `PIPELINE_OFFLINE=1`
(без сетевых обращений, только кэш), `PIPELINE_CACHE` (по умолчанию
`local/pipeline`), `PORT`.

Python-зависимости: `requirements.txt` (локально, SpacePy 0.7.0 = IGRF-13,
валиден до 2025.0) и `requirements-server.txt` (Linux, сборка SpacePy из git с
IGRF-14 до 2030.0 — нужна для текущих дат, требует `gfortran`).

## Архитектура

Сборки нет. `dist/` — браузерные ES-модули, отдаются как есть.

| Слой | Файлы | Назначение |
|---|---|---|
| Вход данных | `dist/providers.js` | `MockDataProvider` (демо) и `ApiDataProvider` с общим `calculate(request, disabled)` |
| Логика оценки | `dist/domain.js`, `dist/pipeline.js` | `validateRequest`, `computePlan` → `assessV2`; чистые функции, без DOM и сети |
| Интерфейс | `dist/app.js`, `dist/pipeline-view.js`, `dist/styles.css` | представления, карта, таймлайн, объяснения |
| Выгрузка | `dist/export.js` | ZIP STORE без зависимостей: `calculation.json`, `sources.json`, `report.html` |
| Загрузчики | `pipeline/adapters.mjs`, `cache.mjs` | один адаптер на источник, файловый контент-адресуемый кэш |
| Качество и модели | `pipeline/quality.mjs`, `orbit.mjs`, `meteor.mjs` | границы величин, версии, выбросы, SGP4, обрезание, Грюн |
| Научный worker | `pipeline/irbem.py` | JSON stdin/stdout: IGRF (L, B, magLat) и AP-8 MIN/MAX |
| Сборка датасета | `pipeline/build.mjs` | `collect()` (сеть) и `buildDataset()` (профиль окна) |
| Сервер | `scripts/serve.mjs` | `POST /v2/eva/dataset`, статика, loopback-only |

Пороги и параметры моделей — данные, а не код: `data/rules.json` (версия
`eva-rules/x.y.z`), таблица метеорных потоков — `data/meteor-showers.json`.
Меняя поведение оценки, правьте правила и поднимайте их версию.

### `docs/` — зеркало `dist/`

`docs/` это копия `dist/` для GitHub Pages. `npm run check` падает с
`Static mirror drift: <файл>`, если они разошлись. **Любая правка в `dist/*.js`,
`*.css` или `*.html` требует копии того же файла в `docs/`.**

### Контракт v2

`docs/api-contract-v2.md` — источник истины. Ключевое отличие от v1
(`docs/api-contract.md`, сохранён только для демо): источник и фактор
развязаны, число источников произвольно, вместо событий-прямоугольников —
**профиль окна**: ряд точек через 30 с вдоль траектории с посчитанными в каждой
`lat/lon/alt`, `L`, `B`, `magLat`, `rc`, `ec`, `saa`, `sunlit`, `sep`,
`trapped`, `gcr`, `meteor`, `ops`. Событие — вывод из профиля, а не вход.

Пять механизмов: `sep`, `trapped`, `gcr`, `meteor`, `ops`. Решающие
(`rules.decisionMechanisms`) — SEP, захваченные частицы, метеоры; контекстные
(`rules.contextMechanisms`) — ГКЛ и сближения.

## Инварианты, которые нельзя нарушать

Это не стилистика, а суть задачи. Каждый пункт покрыт тестом и/или критерием.

1. **Три времени раздельно.** `measuredAt` (прибор зарегистрировал),
   `start`/`end` (воздействие действует), `publishedAt` (данные стали
   доступны). Валидатор требует `measuredAt ≤ publishedAt`.
2. **Неизвестная публикация — это `null`, а не `fetchedAt` и не время
   измерения.** Запись с `publishedAt === null` исключена из строгого replay
   (`selectVersions`), в архивном разборе участвует с явной пометкой.
3. **Отсечение до всего остального.** Replay фильтрует записи *до*
   интерполяции, QA и моделей. Ревизия выбирается по максимальному
   `publishedAt <= cutoff`, а не «итоговая».
4. **Отсутствие данных ≠ отсутствие риска.** Неполное покрытие решающего
   механизма даёт `insufficient`, никогда `acceptable`. Неполное окно не может
   дать подтверждённого улучшения.
5. **Нет тихого отката на демо-данные.** Ошибка API — это ошибка. Недоступный
   источник возвращается со статусом, а не пропускается.
6. **Оценка окна — вектор, не сумма.** Сравнение лексикографическое
   (`compareVector`), порядок задан `rules.ranking.order`. Не сводите механизмы
   к одному баллу: хорошие данные по одному фактору не компенсируют отсутствие
   по другому.
7. **Уверенность — шкала с причинами, не процент.** `{score, level, limiting,
   criteria, reasons}`. Пять критериев оцениваются от 0 до 4, сводная оценка —
   **минимум** по критериям (правило шкалы достоверности NASA-STD-7009), уровень:
   3–4 `high`, 2 `medium`, 0–1 `low`. Каждый критерий несёт `measures` (что
   проверяется), `detail` (состояние сейчас) и `hint` (как поднять). Прогноз
   «последнее наблюдение сохраняется» по критерию `forecast` выше 2 не
   поднимается даже при согласии SWPC: начало события он не предсказывает.
8. **Никакой экстраполяции спектра.** Выше последнего валидного канала GOES
   берётся верхняя оценка (`accessibleFluxBound`, `bound: true`), потому что
   J(≥E) не растёт с E. Ряды разных приборов (`g16`/`g18`/`g19`) не
   склеиваются и не интерполируются друг через друга.
9. **Отброшенная точка не исчезает молча.** Заполнители, вне-диапазонные
   значения, спайки и нарушение порядка интегральных каналов помечаются
   `q: fill|quality|spike|channel_order` и попадают в расчёт покрытия.
10. **Происхождение — перечисление**, не свободная строка:
    `observation | external_forecast | own_computation | model | synthetic`.
    Интерфейс различает наблюдение, внешний прогноз и расчёт команды по этому
    полю.
11. **Прокси называется прокси.** Поток на геостационаре связывается с орбитой
    МКС через жёсткость обрезания (Штёрмер + ослабление CARI-7A при Hp30 ≥ 5).
    Это физический мост, а не подстановка. Освещённость — условие работ, а не
    опасность сама по себе.
12. **Контекстные механизмы не бывают «зелёными».** Пустой top-N экран
    SOCRATES ничего не доказывает; прокси ГКЛ — не доза. Они показываются,
    снижают уверенность, но выбор окна не блокируют.

## Источники

11 источников в `SOURCES` (`pipeline/adapters.mjs`), у каждого — `modes`
(в каких режимах он вообще даёт данные), `factors`, `cadenceMinutes`. Источник
вне своих режимов помечается `applicable: false` — это не сбой и не входит в
«N из M доступных».

GOES SGPS (SEP) · GFZ Hp30 и его ансамблевый прогноз (экран) · NOAA SWPC
3-day forecast (вероятность S1+) · CelesTrak GP и Space-Track GP history
(орбита) · NMDB OULU/ROME (ГКЛ, независимое подтверждение) · SOCRATES
(сближения) · DONKI и NCEI GEOALERT (датированный контекст) · IGRF/IRBEM/AP-8
(локальная модель) · NASA MEO + Грюн (метеоры).

Исторический период задачи — 1 мая — 30 июня 2024. Для полного профиля нужен
однократный импорт OMM из Space-Track (`gp_history` — лимит 1/lifetime, качать
один раз в кэш) и архива GOES через `pipeline/goes_history.py`.

## Стиль кода

- ESM везде, `type: module`. Единственная runtime-зависимость — `satellite.js`.
- Плотный однострочный стиль: несколько операторов в строке, деструктуризация,
  тернарники. Пишите так же, а не «читаемее» — иначе диффы расходятся с
  остальным файлом.
- Комментарии в коде — английские и объясняют **почему** (какое физическое или
  временнóе допущение защищает эта строка), а не что делает код.
- Текст интерфейса, сообщения об ошибках и документация — русские.
- Никаких секретов в `dist/config.js`. Сеть — только через `Cache.fetch`
  (таймаут 12 с, лимит 20 МБ, TTL на источник, отрицательное кэширование
  ошибок).

## Тесты

`tests/pipeline.test.mjs` — ядро: выбор ревизий, QA, SGP4, обрезание по
справочным значениям (12,76 ГВ на экваторе, 0,8 ГВ на 60°, 0,41 ГВ на 65°),
ранжирование, кэш. `tests/planning.test.mjs` — демо-путь v1 и ZIP.
`tests/models.test.mjs` — реальные IGRF/AP-8 и `goes_history.py --selftest`,
пропускается без `PIPELINE_PYTHON`.

Добавляя источник или механизм, проверьте: тест
`empty live dataset validates...` жёстко фиксирует число источников.

## Границы

Это не инструмент допуска к реальной ВКД. Пороги исследовательские, величины —
прокси, а не доза экипажа и не вероятность травмы. `strictReproducibility`
всегда `false`, `limitations[]` заполняется в каждом расчёте и попадает в
выгрузку. Формулировки вида «безопасно» в выводах недопустимы.
