# ОРБИТА — рабочее место аналитика ВКД

Исследовательский планировщик для КосмоХакатона. Локальный запуск включает data-pipeline v2: реальные источники, кэш, проверки качества, SGP4, replay и раздельную оценку механизмов. Статический сайт сохраняет демонстрационный режим.

Подробности, импорт архивов и ограничения моделей: [Data pipeline](docs/data-pipeline.md).

## Быстрый воспроизводимый запуск в Docker

Это рекомендуемый способ для текущего режима 2026 года: образ собирает Node 20,
Python, IRBEM/SpacePy из `requirements-server.txt` и IGRF-14. Исходный код и
данные кэша не вшиваются в образ: кэш сохраняется в локальной папке `local/`.

```sh
docker compose up --build
```

Откройте http://127.0.0.1:5173. Остановить сервис — `docker compose down`;
полученные данные в `local/` при этом сохраняются. Чтобы выполнить проверки в
том же окружении:

```sh
docker compose run --rm app npm test
docker compose run --rm app npm run check
```

Если порт 5173 занят, создайте `.env` по шаблону ниже и добавьте `PORT=8080`,
после чего приложение будет доступно на http://127.0.0.1:8080.

### На сервере за nginx

Контейнер публикуется только на `127.0.0.1` и сам поднимается после сбоя или
перезагрузки сервера (`restart: unless-stopped`); наружу сайт отдаёт nginx.
Кэш, импортированные архивы и файлы SpacePy лежат в `local/` на хосте и
переживают пересборку образа. Команды `docker` выполняются от root или от
пользователя из группы `docker`.

1. Нужен Docker Engine с плагином Compose: `docker compose version`. В Ubuntu:
   `sudo apt install docker.io docker-compose-v2`.
2. Если приложение раньше работало как служба systemd, остановите её, иначе
   порт будет занят: `sudo systemctl disable --now cosmohack.service`. Папка
   `local/` подхватывается как есть: кэш — `local/pipeline`, SpacePy —
   `local/spacepy`.
3. Из корня репозитория соберите образ и запустите контейнер:

   ```sh
   docker compose up -d --build
   ```

   Первая сборка занимает 5–10 минут: компилируется IRBEM. Нужно около 4 ГБ
   на диске и не меньше 2 ГБ памяти.
4. Проверьте: `docker compose ps`, `docker compose logs -f app` и
   `curl -I http://127.0.0.1:5173/`.
5. nginx проксирует на контейнер и передаёт заголовок `Host`: без него API
   отвечает 403 (проверка `Origin`). Расчёт с загрузкой источников может идти
   дольше минуты, поэтому таймаут увеличен:

   ```nginx
   location / {
       proxy_pass http://127.0.0.1:5173;
       proxy_set_header Host $host;
       proxy_read_timeout 180s;
   }
   ```

6. Обновление: `git pull && docker compose up -d --build`.

Разовые команды выполняются в том же образе, результат остаётся в `local/`:

```sh
docker compose run --rm app python pipeline/goes_history.py --from 2024-05-01 --to 2024-06-30
docker compose run --rm app npm run pipeline:import -- records local/goes-history.json
```

## Локальный запуск без Docker

Нужен Node.js 20+.

```sh
npm ci
npm run dev
```

Откройте http://127.0.0.1:5173. Этот запуск работает без Python, но магнитный
профиль IGRF/AP-8 тогда остаётся неизвестным. Для исторического периода 2024
года можно подключить локальные зависимости из `requirements.txt`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:PIPELINE_PYTHON = (Resolve-Path .venv/Scripts/python.exe).Path
npm run dev
```

`requirements.txt` фиксирует SpacePy 0.7.0 с IGRF-13 и подходит только до
2025 года. Для текущего режима используйте Docker: он устанавливает зависимости
из `requirements-server.txt`, включая сборку SpacePy с IGRF-14. Требования в
`pipeline/requirements.txt` повторяют минимальный локальный набор для утилит
импорта NetCDF.

Проверки: `npm test` и `npm run check`.

## Space-Track и историческая орбита

Space-Track всё ещё используется, но **только** чтобы один раз получить
исторические OMM-элементы МКС (`gp_history`) для полного исторического профиля.
Он не нужен для текущего режима, демонстрации, запуска API или данных GOES.
Сервис не читает пароль и не загружает историю автоматически.

1. Создайте аккаунт на [Space-Track](https://www.space-track.org/), примите
   условия доступа к данным.
2. Скопируйте шаблон и внесите учётные данные. Файл `.env` игнорируется Git:

   ```powershell
   Copy-Item .env.example .env
   ```

   В macOS/Linux: `cp .env.example .env`.

3. Откройте `.env` и замените `SPACE_TRACK_IDENTITY` и
   `SPACE_TRACK_PASSWORD`. Чтобы сменить учётные данные позже, достаточно
   изменить эти две строки — ни Dockerfile, ни код править не нужно.
4. Явно загрузите архив и импортируйте его в локальный кэш:

   ```sh
   npm run spacetrack:fetch
   npm run pipeline:import -- omm local/space-track/gp_history-25544.json
   ```

   В Docker та же операция выглядит так:

   ```sh
   docker compose --profile archive run --rm space-track
   docker compose run --rm app npm run pipeline:import -- omm local/space-track/gp_history-25544.json
   ```

Команда получает только NORAD 25544 и не печатает пароль. `gp_history` может
иметь ограничение на число обращений по политике Space-Track, поэтому команда
не вызывается при обычном запуске и архив после первой загрузки стоит сохранить.

## Пример экспорта «Сохранить расчёт»

В [examples/eva-2026-09-20](examples/eva-2026-09-20/README.md) добавлен
реальный пример ZIP-выгрузки из интерфейса: `calculation.json`, `sources.json`
и автономный [report.html](examples/eva-2026-09-20/report.html). Он показывает
формат результата кнопки «Сохранить расчёт» и может быть открыт локально в
браузере.

## Сценарии

- Параметры ВКД: 1–8 часов, поиск сдвига вперёд до 24 часов с шагом 1 час.
- Блок «Окна и обстановка» с двумя режимами на общей шкале времени и с общим выбранным окном. «Обстановка» — таймлайн факторов (SEP у станции, прогноз бури S1+ SWPC, шкала S на GOES, буря Hp30, ЮАА, сближения, уведомления DONKI/NCEI, освещённость, пробелы данных) и дорожки только подходящих окон. «Все окна» — таблица кандидатов с оценками механизмов, местом в ранжировании и уверенностью.
- Рекомендация: все хорошие окна по порядку выбора либо два лучших доступных, объяснение выбора и разбор уверенности по критериям.
- Космическая погода и событийные предупреждения о сближениях. Сближения не подменяют модель всего фонового MMOD.
- Интерактивная карта, выбор окна, временного диапазона, масштаба и момента на траектории.
- Необязательное ограничение освещённости использует те же синтетические орбитальные отсчёты, что карта.
- Архивный разбор и Replay с отсечением по времени публикации. Поздние наблюдения доступны только в отдельной ретроспективной сверке.
- Отключение источников, пересчёт статуса и уверенности, обновление данных.
- ZIP-экспорт: `calculation.json`, `sources.json`, `report.html`. HTML можно распечатать в PDF. Сохранённые расчёты хранятся локально в браузере (до 15 записей).

## Архитектура и подключение API

`dist/providers.js` — точка получения данных. `MockDataProvider` и `ApiDataProvider` предоставляют одинаковый `calculate(request, disabledSources)` и возвращают `{ plan, data }`. Локальный сервер подключает `/v2/eva/dataset` автоматически. [Контракт v2](docs/api-contract-v2.md) развязывает источники и факторы; [v1](docs/api-contract.md) сохранён для демо. При ошибке API нет скрытого переключения на фейковые данные.

`pipeline/` содержит загрузчики, файловый кэш, QA, построение профиля и Python worker IGRF/AP-8. `dist/pipeline.js` оценивает окна вектором, `dist/pipeline-view.js` показывает покрытие и причины неопределённости. Настраиваемые пороги — `data/rules.json`. Python-зависимости опциональны; инструкции установки приведены в документации пайплайна.

`dist/domain.js` — чистая логика оценки без DOM. `dist/app.js` — представления и взаимодействия. `dist/export.js` — автономный ZIP-экспорт. `dist/styles.css` — адаптивный интерфейс. `dist/assets/world.json` — локальная подложка карты.

## Границы прототипа

Это не инструмент допуска к реальной ВКД. В API используются реальные данные и SGP4, но правила остаются исследовательскими. Уверенность v2 качественная: пять критериев по шкале 0–8, сводная оценка — минимум по критериям (правило шкалы достоверности расчётов NASA-STD-7009), у каждого критерия названо, что проверяется и как поднять уровень. Уровни: высокая 6–8, средняя 4–5, низкая 0–3. Это не вероятность безопасности. Решают механизмы с порогами (SEP, захваченные частицы, метеороиды); ГКЛ и сближения — контекст. SEP оценивается по справочнику «Внешние опасности»: дипольное обрезание, ослабление CARI-7A в бурю, оценки сверху там, где спектр GOES заканчивается, и базовый прогноз «последнее наблюдение сохраняется» для будущих часов. Прогнозная полоса ограничена 4 и градуируется по расстоянию от последнего замера; точная заблаговременность показывается в таблице окон. Исторический режим сопоставляет вывод модели с датированными отчётами NASA DONKI. Метеорный поток — фон Грюна с границей из выпусков NASA MEO. Для полного исторического профиля нужен импорт OMM Space-Track и архива GOES (`pipeline/goes_history.py`). SpacePy 0.7.0 с PyPI содержит IGRF-13 (до 2025.0): для текущих дат на сервере ставится `requirements-server.txt` с IGRF-14, подробности — в [Data pipeline](docs/data-pipeline.md). Полная строгая воспроизводимость не заявляется. В статическом демо значения и траектория синтетические.

## Деплой

Сайт — статический ES-module frontend. Для обычного хостинга достаточно содержимого `dist/`, сборка не нужна.

Для GitHub Pages подготовлена папка `docs/`. После загрузки репозитория на GitHub откройте **Settings → Pages**, выберите **Deploy from a branch**, затем ветку `main` и папку `/docs`, после чего нажмите **Save**. GitHub покажет ссылку на опубликованный сайт на той же странице.

Все данные будущего API передаются через HTTPS; CORS разрешает origin фронтенда. Секреты в `config.js` не размещать.

## Географическая подложка

Упрощённые границы из [datasets/geo-countries](https://github.com/datasets/geo-countries), основаны на Natural Earth; исходные географические данные public domain. Это географическая визуализация, а не оперативный источник положения МКС.
