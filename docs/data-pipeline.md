# Data pipeline v2

Локальный Node API заменяет демонстрационный вход данных. `npm run dev` обслуживает
интерфейс и `POST /v2/eva/dataset` на одном origin. При сбое отдельного источника
возвращается его состояние; скрытого перехода на моковые данные нет.

## Запуск

```powershell
npm ci
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:PIPELINE_PYTHON = (Resolve-Path .venv/Scripts/python.exe).Path
$env:SPACEPY = (Join-Path (Get-Location) 'local/spacepy')
npm run dev
```

Python нужен только для IGRF/AP-8 и импорта NetCDF. Без него загрузчики, SGP4,
кэш, API и интерфейс работают; магнитный профиль остаётся неизвестным.
`requirements.txt` ставит SpacePy 0.7.0 с IGRF-13: этого хватает для исторического
периода 2024 года, но не для текущих дат (см. ограничения).

### Сервер (Linux): текущий режим и IGRF-14

SpacePy 0.7.0 — последний выпуск на PyPI, его IGRF-13 действителен до 2025.0. IRBEM с
IGRF-14 (до 2030.0) есть в ветке main SpacePy с 27.01.2025; `requirements-server.txt`
закрепляет проверенный коммит и собирает его из исходников, нужен gfortran:

```sh
sudo apt install gfortran python3-dev python3-venv git
python3 -m venv .venv
.venv/bin/pip install -r requirements-server.txt
```

Процессу API нужны `PIPELINE_PYTHON=<репозиторий>/.venv/bin/python` и
`SPACEPY=<репозиторий>/local/spacepy` (каталог настроек SpacePy, доступный на запись).
Worker сам определяет поколение IGRF по библиотеке и отказывает для дат вне его области.
`PIPELINE_OFFLINE=1` отключает сетевые обращения; `PIPELINE_CACHE` меняет каталог
кэша, `PORT` — порт (по умолчанию 5173). GitHub Pages остаётся статическим демо:
для реальных данных ему требуется отдельно размещённый API.

## Загрузка и импорт

```powershell
npm run pipeline:fetch -- data/request.example.json local/history.json
npm run pipeline:build -- data/request.example.json local/history-offline.json
npm run pipeline:import -- omm local/gp_history.json
npm run pipeline:import -- goes local/integral-protons.json
.\.venv\Scripts\python.exe pipeline/import_netcdf.py local/goes.nc local/goes-records.json
npm run pipeline:import -- records local/goes-records.json
```

`fetch` получает источники для периода запроса, затем сохраняет `{dataset,plan}`.
`build` использует только кэш. Импорт также поддерживает `hp30`, `nmdb`,
`socrates`, `donki`, `geoalert` и нормализованные `records`.
Исторические OMM Space-Track загружаются пользователем один раз и импортируются:
программа не запрашивает пароли и не повторяет ограниченный `gp_history`.

## Стадии

1. Сохраняется неизменённый ответ, URL, SHA-256, время загрузки; нормализованные
   записи сохраняются отдельно. Кэш исключён из Git.
2. Проверяются идентичность, UTC, происхождение и `measuredAt <= publishedAt`.
   Измерение, публикация, загрузка и интервал воздействия — отдельные поля.
3. На строгом replay исключаются неизвестные и поздние публикации; выбирается
   последняя известная ревизия по источнику, ряду, прибору и времени измерения.
4. Ряды разделяются по спутнику/датчику, сортируются и дедуплицируются. Заполнители,
   QA-флаги, одиночные спайки и нарушения порядка интегральных каналов становятся
   `null` с причиной. Они не заменяются медианой и не исчезают из покрытия.
5. GOES интерполируется только между валидными точками с разрывом до 15 минут;
   Hp30 удерживается максимум 60 минут после конца измерительного интервала.
   NMDB использует имена из заголовка ответа и конец часового интервала.
6. SGP4 распространяет OMM МКС (25544) на сетку 30 секунд. Элементы старше
   24 часов или будущей эпохи не используются. Освещённость учитывает геометрию
   земной тени; карта использует те же отсчёты.
7. Дополнительный worker SpacePy вычисляет IGRF, L, B, магнитную широту,
   AP-8 MIN/MAX. Поколение IGRF определяется по библиотеке, даты вне его области
   не считаются. Заполнитель IRBEM при L ≤ 11 означает лог-поток карты AP-8 ≤ 0,
   то есть поток ниже 1 см⁻²с⁻¹ (конус потерь, внутренняя граница пояса): это 0 с
   флагом `ap8Floor`, а не неизвестность. Неизвестным остаётся только L > 11.
8. Обрезание — вертикальная формула Штёрмера для центрированного диполя
   `Rc = 14,5·cos⁴λm/(r/R)²` ГВ, при Hp30 ≥ 5 — ослабление экрана CARI-7A
   `0,5·Rc·(1 + 0,54·e^(−Rc/2,9))` (справочник «Внешние опасности», §2.4 и
   приложение Б). Rc переводится в энергию протона; доступный поток — интегральный
   канал GOES выше max(Ec, 30 МэВ): 30 МэВ пробивает скафандр (табл. 3 справочника).
   Спектр не экстраполируется: выше последнего канала (500 МэВ) берётся верхняя
   оценка J(≥500 МэВ), без геомагнитного индекса — J(≥30 МэВ) без экрана
   (`sepBound`). Одновременные показания разных приборов не усредняются.
9. В текущем режиме после последнего замера GOES действует базовый прогноз
   справочника (§6.4) «последнее наблюдение сохраняется», не дольше 72 ч
   (`sepBasis: persistence`). Обрезание для будущих часов берётся по максимуму
   ансамблевого прогноза Hp30 GFZ. Начало события такой прогноз не предсказывает,
   поэтому уверенность таких окон низкая, а в причинах указано время замера.
   Покрытие рядов и интервалы пробелов вычисляются на всём горизонте.
10. Окна получают отдельные экспозиции, статусы и покрытие механизмов. Решают
    механизмы с порогами (`decisionMechanisms`: sep, trapped, meteor). ГКЛ и
    сближения (`contextMechanisms`) полностью не наблюдаемы: они показаны, снижают
    уверенность, но выбор не блокируют. Ранжирование лексикографическое:
    неполнота, проверки, SEP, время ЮАА, конфликты, при включении — тень, затем
    начало. Числа разных размерностей не складываются. Равенство и неполные
    данные не порождают рекомендацию.
11. Уверенность — уровень с объяснениями, не процент вероятности. Правила,
    ограничения, источники и профиль входят в JSON/ZIP-экспорт.

## Проверенные источники

Проверка публичными запросами 19.09.2026; результаты относятся к этой проверке.

| Источник | Подключение | Строгий replay |
|---|---|---|
| GOES SWPC | Живой JSON, восемь интегральных каналов, satellite сохранён | Нет времени публикации |
| GOES NCEI | Реальный NetCDF 10.05.2024: 40 320 записей, два датчика | Нет времени публикации; date_created не подменяет его |
| GFZ Hp30 | Исторический JSON проверен; UTC без миллисекунд | Без датированного nowcast непригоден |
| GFZ Hp30 прогноз | Ансамбль SWIFT на 3 суток, шаг 30 мин; берётся максимум ансамбля | Только текущий режим; время выпуска не публикуется |
| CelesTrak GP | Реальная OMM МКС; TTL 120 минут | EPOCH не публикация |
| Space-Track | Импорт OMM с CREATION_DATE | Да для импортированных датированных записей |
| NMDB | OULU/ROME, ASCII внутри HTML, порядок из заголовка | Нет времени публикации |
| SOCRATES | CSV, фильтр обеих сторон по 25544 | Нет публикации; top-N неполон |
| DONKI | Датированные notifications за исторический период | По messageIssueTime; только контекст |
| NCEI GEOALERT | Выпуски 10–11.05.2024, Issued из текста | Да для выпусков, не для выдуманного прогноза из них |
| IGRF/AP-8 | SpacePy 0.7.0 (IGRF-13, 2024) и сборка main с IGRF-14 (2026) проверены | Версия модели и поколение IGRF указаны |
| NASA MEO | Фон Грюна × граница из выпусков LEO forecast 2024 и 2026 | Да: дата выпуска MEO в каждой записи |

Реальные ограничения, которые нельзя скрывать:

- SpacePy 0.7.0 содержит IGRF-13 с границей 2025.0. Worker определяет поколение
  IGRF и для дат вне его области явно отказывает: IRBEM иначе молча использует
  ближайший год, и эта подмена запрещена. Для текущих дат нужна сборка из
  `requirements-server.txt` (IGRF-14, до 2030.0).
- Обрезание — дипольная формула с эмпирическим штормовым ослаблением CARI-7A.
  Разные модели дают заметно разное ослабление экрана: это главная модельная
  неопределённость SEP. Выше 500 МэВ и без индекса используется оценка сверху.
- AP-8 MIN/MAX обозначают фазы солнечного цикла, а не нижнюю/верхнюю границу потока.
  Для прокси берётся максимум двух доступных вариантов; оба сохраняются в профиле.
- Архив SGPS L2 содержит 13 дифференциальных каналов и один интегральный >500 MeV
  на каждый датчик. Он не равен восьми интегральным каналам SWPC. Дифференциальный
  спектр пока сохраняется и проверяется, но не реконструируется в интегральный.
- NMDB отображается как независимый наземный контекст. Калиброванной модели
  локального ГКЛ вдоль орбиты нет: механизм `gcr` остаётся unknown и считается
  контекстом — за время окна ГКЛ практически не меняется (справочник, §2.1, §7).
- Метеорный поток — оценка сверху: спорадический фон Грюна (1985) с поправками на
  Землю (SPENVIS) для 420 км и массы ≥ 3,35·10⁻⁵ г (6,7 Дж — порог пробития
  скафандра по NASA MEO) × 2, потому что по выпускам MEO 2024 и 2026 при этой
  энергии фон превышают только Геминиды. Окна Геминид (пик ± 7 сут) и годы без
  выпуска MEO не оцениваются. Модели отличаются в несколько раз: для 8-часового
  окна оценка 8,7·10⁻⁵ ударов близка к порогу METEOR-01 (10⁻⁴).
- SOCRATES не даёт полного покрытия, поэтому `ops` не получает зелёный статус
  только из-за отсутствия найденных событий. Это контекст: сближения в окне
  показываются и учитываются в ранжировании, но выбор не блокируют.
- ACE EPAM, NASA OEM, калибровка штормового обрезания, реконструкция спектра,
  полный эксперимент FAR/заблаговременности пока не реализованы. DONKI/NCEI
  подготовлены как входы будущего эксперимента. `strictReproducibility` остаётся false.

Это работающий слой загрузки, качества, профиля и оценки с честными неизвестными,
а не завершённая научно верифицированная модель всех механизмов.

## Формат метеорного входа

Одна запись должна описывать **полный** абсолютный поток для непересекающегося
интервала, включая фон, а не только относительное усиление отдельного потока:
`{start,end,publishedAt,sourceVersion,sourceUrl,massThresholdG,fluxM2Second}`.
Количество пересечений площади: `fluxM2Second * suitAreaM2 * seconds`.
Пересекающиеся записи не суммируются автоматически: результат unknown.
Таблица генерируется `npm run meteor:table` (`scripts/meteor-table.mjs`); новый выпуск
NASA MEO (обычно в октябре на следующий год) добавляется в список `RELEASES`.

## Проверки

`npm test` — тесты replay, QA, интерполяции, реальной SGP4, ранжирования и кэша.
При заданном `PIPELINE_PYTHON` дополнительно запускаются реальные тесты IGRF/AP-8.
`npm run check` — синтаксис и совпадение файлов статических `dist/` и `docs/`.
В ограниченных Windows-средах тесты можно запускать без дочерних процессов:
`node --test --test-isolation=none tests/*.test.mjs`.

Реализации сверены с [CelesTrak GP](https://celestrak.org/NORAD/documentation/gp-data-formats.php),
[satellite.js](https://github.com/shashwatak/satellite-js),
[GFZ Hpo](https://kp.gfz.de/hp30-hp60/ueber-hpo) и
[SpacePy IRBEM](https://spacepy.github.io/autosummary/spacepy.irbempy.html).
